📘 Arquitectura y Funcionamiento Integral del Sistema BQS Miramar
1. Red LoRa Mesh & Enrutamiento Multi-Hop

El sistema BQS supera las limitaciones de alcance de línea de vista directa en mar abierto mediante una red en malla dinámica basada en RadioHead RHMesh (1.8x) sobre 915 MHz:

  • Saltos Múltiples (Relaying): Cada boya transmite su propia telemetría y a la vez actúa como repetidor para boyas ubicadas mar adentro.
  • Tolerancia a Desconexión (Store-and-Forward): Si una boya no encuentra ruta hacia la costa, retiene hasta 32 tramas en memoria local circular y las reenvía al reconectar.
  • Anti-Looping: Tabla de paquetes vistos por (source_node, sequence) para evitar tormentas de retransmisión.
2. Protocolo Binario Compacto (34 Bytes)

Optimizado para minimizar el tiempo al aire (Time on Air) y maximizar la autonomía energética:

3. Sensores e Instrumentación Física
  • Temp. Agua Superficial: Sensor digital sumergible Dallas DS18B20 montado en la quilla estabilizadora inferior (Pin D6, OneWire).
  • Temp. y Humedad de Aire: Sensor digital DHT22 / AM2302 en torre superior ventilada (Pin D5).
  • Posicionamiento Geodésico: Receptor satelital u-blox NEO-6M / M8N con antena activa para geolocalización y sincronización UTC.
  • Monitor de Batería: Divisor resistivo en Pin A0 con divisor $5.5454\times$ para acumuladores Li-ion 1S/2S. Alerta automática a $< 3500\text{ mV}$.
  • Transceptor de Radio: Módulo HopeRF RFM95W (Semtech SX1276) con potencia de emisión a +20 dBm (100 mW).
4. Estación Base Gateway & Servidor Central
  • Gateway Raspberry Pi 3: Receptor serie LoRa con decodificador binario, base de datos local SQLite spool.db (para no perder datos ante caídas de enlace celular 3G) y cliente uploader HTTP.
  • Balizas (Beacons): Emisión periódica de tramas de sincronización para que las boyas elijan la ruta óptima por calidad de señal (RSSI).
  • Servidor REST: Deduplicación estricta UNIQUE(node_id, sequence) para procesar tramas recibidas por múltiples gateways sin duplicar registros.
